About this list

Awesome Computed Tomography is an independent, hand-curated map of research on CT image reconstruction: the papers, open-source toolkits, datasets, benchmarks and learning material a researcher needs to find their way into the field, kept in one place and checked by hand.

What it covers

The list currently holds {{N_PAPERS}} papers from {{YEAR_MIN}} to {{YEAR_MAX}}, {{N_TOOLKITS}} toolkits, {{N_DATASETS}} datasets, {{N_BENCHMARKS}} benchmarks and {{N_LEARNING}} learning resources. Papers are grouped by problem (sparse-view, limited-angle, low-dose, metal artifacts, spectral, cone-beam, dynamic and 4D CT, scatter, calibration and motion) and by method family (classical and iterative solvers, deep unrolling, self-supervised methods, diffusion and generative priors, implicit neural representations, Gaussian splatting).

It is a reading list, not a database of everything. An entry is included because it is useful to someone working on CT reconstruction: a method people build on, a strong baseline, a dataset or benchmark that results are reported on, or a clear introduction.

How entries are verified

  • Identity. Every paper link is resolved against Crossref, arXiv or the publisher’s own record, and the title is matched against that record, so an entry cannot quietly point at a different paper.
  • Venue. {{N_PEER}} papers ({{PEER_PCT}}%) carry a peer-reviewed venue, confirmed from the DOI rather than from search results. The other {{N_PREPRINT}} are marked preprint and dated by their first public posting.
  • Links. Every URL is checked. Code links point at the authors’ own repositories where they exist.

Checks catch broken links and mismatched records, not every mistake. A venue, a year or a category can still be wrong. If a detail matters for your work, follow the link and rely on the original paper.

What it is not

An entry is a pointer to someone else’s work, never a copy of it. Titles, venues and links are facts about papers that belong to their authors and publishers; inclusion is not an endorsement by them, and is not a claim that results have been reproduced here. Nothing on this site is medical advice.

Maintenance

The list is curated and maintained by its authors and updated continuously, with new arXiv papers, corrected venues and repaired links. It does not accept outside pull requests. Suggestions and corrections are welcome through the contact page, and each one is checked before anything is added. Every change is recorded, dated, in the changelog.

The same data is published as the GitHub README and as data.json. Both are generated from the same source files, so they never disagree with this site.

Frequently asked questions

Which datasets are best for sparse-view CT?

The most widely used are LoDoPaB-CT and the Mayo Clinic LDCT-and-Projection-data, from which sparse sinograms are simulated, and the AAPM DL-Sparse-View CT challenge data, which isolates the sparse-view problem with noiseless 128-view sinograms. For measured rather than simulated data, use 2DeteCT, the FleX-ray walnut collection or SparseBeads. The sparse-view CT topic page lists them next to the key papers, and the dataset table has all {{N_DATASETS}} datasets.

Which open-source toolkits are used for low-dose CT research?

For reconstruction, the ASTRA Toolbox, TIGRE, ODL and the Core Imaging Library (CIL) provide projectors and iterative solvers, and DeepInverse and LION add learned and unrolled methods in PyTorch. To create realistic low-dose data from full-dose images, use the LD-CT simulator. See the low-dose CT topic page and the toolkit table.

How can I suggest a paper or report a mistake?

Open a GitHub issue or send an email, as described on the contact page. For a paper, send its DOI or arXiv link and, if there is one, its code repository and the topic it belongs to. The list does not accept outside pull requests, and every suggestion is checked before anything is added.
